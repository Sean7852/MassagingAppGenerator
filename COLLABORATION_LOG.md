# Collaboration Log

A running record of how this project was built: what the human author did, what the AI assistant
did, and how the two worked together. It is updated with every major commit.

- The [README](README.md) says which **artifacts** are hand-crafted and which are generated by the harness.
- This file says **who did the work behind each step**, and how much of the hand-crafted work was AI-assisted.

| AI assistant (pair, while authoring) | Claude Code, model Claude Opus 5.5 (from 2026-10-11) |
| Earlier AI assistant | Codex. Drafted the first plan on 2026-10-10, then replaced (see log) |
| AI generator (inside the harness) | Claude Code sub-agents driven by `/generate`. Its output is only `clients/`, logged as `gen:` commits |

## Working agreement

1. **The human owns decisions.** Scope, language and stack choices, trade-offs and what gets
   committed are the human's call. The AI proposes and recommends but does not decide.
2. **The AI drafts and analyzes.** Analysis, plans, spec drafts, harness code, scripts and docs may
   be drafted by the AI. The human reviews them and asks for changes before they are committed.
3. **AI defaults are flagged.** When the AI has to pick something the human hasn't decided yet,
   it says so and the choice is logged below as *pending confirmation*.
4. **Generated code is never hand-edited.** Fixes to `clients/` go through the spec or the
   harness and are then regenerated, by either party.
5. **The human makes the commits.** The AI only commits when asked to, and its commits carry a
   `Co-Authored-By` line.
6. **This log is updated with every major commit.** One entry per milestone or significant commit.

## Entry template

```markdown
### YYYY-MM-DD — <milestone / title>  (`<commit hash>` or *uncommitted*)
**Human:** what the human did, decided or wrote.
**AI:** what the AI drafted, analyzed or built.
**How we worked:** the flow, e.g. human question → AI proposal → human decision → AI revision.
**Decisions:** decisions made, and by whom.
**Open:** anything pending confirmation or deferred.
```

### 2026-10-11 — Server draft and protocol decisions  (*uncommitted*)
**Human:** Asked for a Python server draft. Asked for an explanation of the outbox flush options
(one at a time vs pipelined), then made the protocol decisions below.
**AI:** Wrote `server/server.py` (in-memory, `websockets`, store-and-forward with per-user mailboxes,
dedup by `(sender, id)`, redelivery until `deliver_ack`, ordered per-connection writes,
`LISTENING port=N` for test runners), the draft `server/PROTOCOL.md`, and `requirements.txt`.
Ran a throwaway protocol-level smoke test of the Alice/Bob scenario, dedup on resend, and session
replacement; it passed. Then, at the human's request, turned it into
`server/test_server.py` (18 protocol tests, standard library + `websockets`; all pass, and breaking
dedup on purpose makes one fail). Explained the trade-offs of the flush options and recommended one at a time.
**How we worked:** Human request → AI draft with defaults flagged as pending → human asked for an
explanation of one open point → AI explained with a recommendation → human decided.
**Decisions:**
- Human (accepting AI defaults): names match `^[a-z0-9_]{1,32}$`; on a second login with the same
  name the newest connection wins; messages to never-seen users are held until they log in.
- Human (accepting AI recommendation): clients flush the outbox **one message at a time**.
**Open:**
- `server/PROTOCOL.md` still has to move into `spec/core/10-protocol.md`.
- Whether `login` needs a protocol version field.
- The Alice/Bob scenario still has to become a conformance scenario run through real clients.
