# 00 — Overview

## Actors
- **Server**: one process, in memory, hand-written (`server/server.py`). It routes and stores
  messages. It is the only authority on names, message validity and message order.
- **Client**: a command-line program, one per platform, generated from this spec. A human or a
  test runner drives it through stdin and reads its stdout.
- **User**: a name. There are no passwords; whoever logs in with a name is that user.

## Terms
| Term | Meaning |
|---|---|
| frame | one JSON object sent as one WebSocket text message ([10-protocol.md](10-protocol.md)) |
| message | a text from one user to another, identified by `id` |
| `id` | a message id: a random (version 4) UUID in lowercase, generated by the sending client |
| `seq` | a positive integer the server assigns to a message when it first accepts it |
| online | the client has a connection and has received `login_ok` |
| offline | the client has a saved name but no connection (by choice, or because it was lost) |
| outbox | messages the user has sent that the server has not accepted or rejected yet; saved on disk |
| data directory | where one user's name and outbox are saved ([40-storage.md](40-storage.md)) |
| output line | one line the client writes to stdout ([30-cli.md](30-cli.md)) |

## Invariants
1. A message is identified by the pair (sender name, `id`). Sending the same pair twice is the
   same message, never two.
2. The server assigns `seq` once per message. `seq` values strictly increase in the order the
   server accepts messages.
3. A client shows each received message at most once per run, in the order it arrives.
4. A client has at most one message waiting for the server's `ack` at any time.
5. A message the user sent is never lost by the client: it stays in the outbox, on disk, until
   the server accepts it (`ack`) or rejects it (`error` with `ref`), across disconnects,
   restarts and crashes.
6. Everything a client does that anyone else can observe (frames sent, lines printed) is
   defined by core and extension modules. Platform modules never change it.

## Scope of spec version 2
- Version 1: log in by name, send a text to a user, receive texts, see errors.
- Version 2 adds: going offline and online on command (`/offline`, `/online`), sending while
  offline into an outbox that is saved on disk and sent on reconnect, and remembering the name,
  so later launches log in by themselves. A lost connection leaves the client `offline`; it
  reconnects only when the user types `/online`.
- Out: automatic reconnecting, several users per data directory, logging out.
