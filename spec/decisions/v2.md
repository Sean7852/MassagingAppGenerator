# Decisions — spec version 2

Offline outbox, saved name and outbox, `/offline` and `/online`. Same conventions as
[v1.md](v1.md). Decisions in v1 still hold unless replaced here.

| # | Decision | Why | By |
|---|---|---|---|
| D12 | With a saved name, the client goes online by itself at startup (as if `/online` was typed). | The assignment asks for login "on first launch"; later launches should not ask again. | Human, on AI recommendation, 2026-10-11 |
| D13 | Every `/send` prints `QUEUED` at once (online or offline), and `SENT` later on `ack`. Replaces v1, where an online `/send` printed nothing until `SENT`. | The same lines whatever the connection state at that instant, so output never depends on timing. | Human, on AI recommendation, 2026-10-11 |
| D14 | A lost connection leaves the client `offline` with its outbox intact; it reconnects only on `/online`. No automatic retry. Replaces v1's `not_sent` errors (D10). | Deterministic and testable; nothing is lost any more. | Human, on AI recommendation, 2026-10-11 (also PLAN.md §6) |
| D15 | The saved state has an exact, shared format: `<data-dir>/state.json` with `version`, `name`, `outbox`, written atomically (temp file + rename) before the output line that reports the change. | Both clients store the same thing the same way; inspectable; fewer choices for the generator; a printed line means the change is on disk. | Human, on AI recommendation, 2026-10-11 |
| D16 | `/offline` closes the connection and prints `OFFLINE`; `/online` reconnects. Both are simulated network loss, not a protocol feature. | The assignment's scenario needs deterministic offline and online moments (PLAN.md §6). | AI default, pending confirmation |
| D17 | Default data directory `.msgdata` in the working directory; one data directory per user; `/login` only works when no name is saved (no logout, no user switching). | Smallest model that covers the assignment. Two users on one machine use two data directories. | AI default, pending confirmation |
| D18 | A state file that cannot be loaded or saved makes the client exit with status 1 (message on stderr), never discard saved messages. | Losing a user's unsent messages silently is the worst outcome. | AI default, pending confirmation |
| D19 | The seen set is not saved. After a restart, a redelivered message may be shown again. | Redelivery after a restart needs a lost `deliver_ack`, which is rare; saving the seen set forever is not worth it yet. | AI default, pending confirmation |
| D20 | New local error codes `already_online` and `already_offline`; `already_logged_in`'s message becomes `already logged in`; `not_logged_in` now also covers `/online` and `/offline` before any login. | Every command in every state has exactly one defined outcome. | AI default, pending confirmation |
